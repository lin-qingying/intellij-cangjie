# 仓颉词法分析经验总结

## 词法分析基本原则
1. 清晰性：语法规则应当简单明确
2. 一致性：相似的语法结构应当有相似的处理方式
3. 可扩展性：设计时应当考虑到未来的语法扩展
4. 错误恢复：提供良好的错误提示和恢复机制

## 表达式处理经验

### 1. unsafe作为原子表达式
#### 设计思路
- 将unsafe块作为不可分割的最小语法单位
- 整体token化处理，不解析内部实现
- 提供明确的作用域边界

#### 实现要点
- 词法分析阶段整体识别
- 保持块级完整性
- 错误处理机制

#### 使用示例
```cangjie
unsafe {
    // 原子化处理的代码块
}
```

### 2. spawn作为原子表达式
#### 设计思路
- spawn表达式作为协程创建的原子单位
- 整体作为单一token处理
- 支持参数传递和上下文捕获

#### 实现要点
- 识别spawn关键字及其作用域
- 处理参数列表和闭包捕获
- 维护协程上下文关系
- 确保资源正确管理

#### 使用示例
```cangjie
spawn {
    // 协程代码块
}

 
```

#### 特殊处理
1. 闭包变量捕获
   - 识别外部变量引用
   - 确保变量生命周期
   - 处理可变性约束

2. 异常处理
   - 协程内异常传播
   - 取消操作处理
   - 资源清理机制

3. 上下文管理
   - 父子协程关系
   - 调度器绑定
   - 作用域控制

### 3. quote作为原子表达式
#### 设计思路
- quote表达式作为元编程的原子单位
- 整体作为单一token处理
- 支持插值表达式和宏属性

#### 实现要点
- 识别quote关键字及其作用域
- 处理插值表达式 ($)
- 处理宏属性 (@)
- 维护token的完整性
- 处理嵌套括号层级

#### 使用示例
```cangjie
quote(x + y)

quote(
    @attr
    function test() {
        $(1 + 2)
    }
)
```

#### 特殊处理
1. 插值表达式处理
   - 识别$符号开始的表达式
   - 解析插值内的表达式
   - 保持插值上下文完整性

2. 宏属性处理
   - 识别@开头的属性
   - 解析属性参数
   - 维护属性作用域

3. 括号平衡
   - 追踪括号嵌套层级
   - 确保括号匹配
   - 处理不同类型括号

4. 转义处理
   - 处理特殊字符转义
   - 保持字面量完整性
   - 维护原始文本结构

## 常见实现模式

### 1. 原子化处理模式
适用场景：
- 需要整体处理的特殊语法结构
- 具有明确边界的代码块
- 内部实现细节不需要词法分析

实现策略：
1. 明确标记开始和结束
2. 跳过内部内容的详细解析
3. 提供完整性验证

### 2. 递归解析模式
适用场景：
- 嵌套结构
- 复杂表达式
- 需要层次化处理的语法

实现策略：
1. 定义清晰的递归规则
2. 处理优先级关系
3. 避免死循环

### 3. 上下文感知模式
适用场景：
- 依赖上下文的语法结构
- 需要类型推导的表达式
- 多态语法结构

实现策略：
1. 维护上下文状态
2. 实现回溯机制
3. 提供上下文验证
